## Reading

The frozen screen answers the r46 question. The retained `display.fb` frame
and the final ramfb frame (SHA-256
`b747ac81a7ef678ac8e1c74ba12a49decb15aa29dde10ae8345fd03e7da8dc4f`) both show
the Windows 11 Start menu open over the blue challenge form, with the cursor
on the Start menu at the screen centre. Windows opens the Start menu at a new
user's first sign-in, and the shell logs of r45 and r46 record
`StartMenuShown` at the desktop switch. So the click and the keys went to the
Start menu.

The agent and the form share session 2 and high integrity, which rules out the
integrity-level and session hypotheses from r46. The form's check of the
window under the screen centre did not see the Start menu, which sits in a
shell layer above ordinary top-most windows. The cursor evidence is not
informative: the form wrote its last progress line before the input, and
Windows starts the cursor at the screen centre.
