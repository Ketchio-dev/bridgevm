## Defects fixed to reach this

1. **MoltenVK emits Metal source that writes an undeclared `gl_CullDistance`
   member**, so `vkCreateGraphicsPipelines` returned `VK_ERROR_INITIALIZATION_FAILED`,
   the renderer registered no object, a later `vkCmdBindPipeline` killed the Venus
   ring, and the blocking readback `Map` never returned. Reproduced standalone and
   confirmed unchanged in MoltenVK 1.4.2; worked around at the PPSSPP layer with
   `Bugs::CULL_DISTANCE_BROKEN` for Venus adapters, which falls back to the
   clip-distance and CPU range-culling paths.
2. **The identity probe collapsed duplicate module names**, hiding the sealed
   title-local `dxgi.dll` behind the system copy. It now reports every module
   sharing a base name.
3. **The Venus ICD expectation came from a host build directory the sealed image
   never used.** It is now pinned to the driver the guest actually installed.
4. **The measurement window began at process launch**, so slow startup consumed it
   and produced zero samples. It now starts at the first presented frame, bounded
   by `StartupGraceSeconds` so a title that never renders still fails.

No threshold, sampler, renderer, timeout or the independent 3/3 policy was
changed; the same gate produced honest failures until the defects above were
fixed.
