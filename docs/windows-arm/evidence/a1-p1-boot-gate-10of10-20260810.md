## Why this differs from the earlier failures

The earlier in-kernel-GIC P1 campaign passed 8/10; two boots entered a
renderer-coupled kick storm. A later pilot on `84538cd` disproved the hypothesis
that same-BootId firstboot re-entry itself caused the failure: Windows accepted
a delayed `shutdown /r /t 5`, but no reset occurred for 40 minutes. Commit
`0f02579` keeps the staged reboot intent alive by retrying it immediately with
`shutdown /r /t 0 /f` when the same BootId task re-enters. A two-boot pilot
passed 2/2 before this independent ten-boot campaign passed 10/10.

The 2026-08-08 userspace-GIC soak remains valid evidence for that alternate
configuration and for A15, but it is not the configuration measured here.
This close is based on the product-default in-kernel-GIC fresh-firstboot gate;
it neither rewrites the older failure record nor claims the userspace-GIC
Venus path is healthy.
